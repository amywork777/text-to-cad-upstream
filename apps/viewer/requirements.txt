# The CAD Viewer's Python dependencies — the interpreter that runs
# `python server/main.py` is the only door cadgen comes through.
#
# The server itself is stdlib-only, so this file installs NOTHING the viewer
# needs in order to start, serve, or render. cadgen is a SOFT dependency of one
# path: importing a foreign .step compiles it in a worker the server owns.
# Without cadgen the viewer still runs and viewing existing models is
# unaffected; the import answers with an install hint instead.
#
# A FLOOR, not a pin, and it names the first release whose build entry point
# accepts the progress sink the import path installs. It is the honest INSTALL
# requirement; it is not how the running server decides whether an import is
# possible — that reads the installed signature, because an editable checkout
# reports the last release's version no matter what its source contains. See
# MINIMUM_CADGEN_VERSION in server/compile_worker.py.
#
# scripts/release/pin-cadgen-requirements.sh deliberately does NOT rewrite this
# line, and a `cadgen>=` spelling does not match its bare-name pattern. That
# rewrite exists so a published SKILL resolves one exact release from PyPI; this
# app is mirrored to earthtojake/cad-viewer as a standalone repo, where "at
# least this new" is what a user wants and a pin would fight whatever newer
# cadgen they already have.
#
# In THIS repo, install requirements-dev.txt instead: it puts cadgen on the
# interpreter as an editable install of packages/cadgen, which is the copy a
# contributor is actually changing.
cadgen>=0.4.29
