# Posts: the G-code dialects

A post turns each setup's toolpaths into one program for a controller, written beside the part as
`<part>.<setup id><extension>`. Pick it with `machine.post` (left out, the kind's default: see
[job-file.md](job-file.md), which also has the machine keys every post shares). The keys below are the
post's own: put them in `machine` next to `kind` and `post`; a key another post takes is refused.

```json
{"machine": {"kind": "lathe", "post": "fanuc", "cycles": true, "program_number": 2001}}
```

```
cadgen cam plan part.step --job job.cam.json
```

## The safety header

Every program opens with comments: the part, setup and post; generated by cadgen, NOT proven on a
machine; air-cut it or run it single-block first; verify the work offset and every tool length; units mm,
feeds and speeds are starting points; the material and every tool. Then the post's own notes (diameter or
radius X on a lathe, how a 3+2 setup is set up, TCP, how a wire's offset is carried). Nothing sends a
program to a machine. Tell the user this line when you report.

## The posts

| post | file | kinds | what it writes | its machine keys |
| --- | --- | --- | --- | --- |
| `grbl` | `.nc` | mill, router, laser | no tool changer (M0 with a comment), cycles expanded, laser `M4 S` (0-1000), dwell in seconds | none |
| `linuxcnc` | `.ngc` | mill, mill4, mill5, lathe | `G64 P` blending, `T M6` + `G43 H`, G81-G89 (tap as rigid `G33.1`), `M2`; lathe `G7`/`G8`, `G96 D S`, `G95`, one-line `G76`; roughing always expanded | `cycles` |
| `fanuc` | `.nc` | mill, mill4, mill5, lathe | `%` + `O` number, upper-case comments, decimal points, `G91 G28 Z0.` before `T M6`, G73-G89 with `M29` rigid tap, fine bore `G76`, dwell ms, 3+2 `G68.2`/`G53.1`, TCP `G43.4`; lathe `T0101`, `G50 S` + `G96`, `G98`/`G99`, two-block `G76`, `G71` with `cycles` | `cycles`, `program_number` |
| `haas` | `.nc` | mill, mill4, mill5, lathe | as Fanuc, plus `T M06`, rigid tap without M29, air `M83`/`M84`, 3+2 by `G254` dynamic work offset, TCP `G234`, `G187` smoothing; lathe `T101`, one-block `G76 X Z K D F A` and `G71 P Q U W D F` | `cycles`, `program_number`, `smoothing` |
| `mach3` | `.tap` | mill, mill4, router, plasma | `G91.1` (incremental arc centres), `T M6` + `G43 H`, G73-G89 (left-hand tap, fine bore expanded), dwell in seconds; plasma torch `M3`/`M5` with heights | `cycles`, `dwell_ms`, the torch keys (THC off by default) |
| `marlin` | `.gcode` | laser | `G21 G90`, `M3`/`M4 S` on Marlin's scale, `G4 P` ms, air assist `M8`/`M9`, ends `M5` (Marlin's M30 deletes a file), no work offsets | `laser_scale`, `laser_mode`, `inline_power`, `z_words` |
| `plasma` | `.nc` | plasma | per cut: pierce height, `M3`, pierce delay, cut height, THC on; then THC off, `M5`, safe height; `M30` | the torch keys, `dwell_ms` |
| `waterjet` | `.nc` | waterjet | per cut `M3`, pierce dwell, `M5`; X Y only; `M30` | `pierce_s`, `z_words`, `dwell_ms` |
| `wire_edm` | `.nc` | wire_edm | `%` + `O`, `G92 X Y` at the first start hole, `G40` (offsets applied), thread/cut codes between start holes, taper `G51`/`G52 A` + `G50`, `M30` | `wire_comp`, `uv_words`, `wire_thread`, `wire_cut`, `program_number` |

## The machine keys

| key | posts | values (default) | what it changes |
| --- | --- | --- | --- |
| `cycles` | linuxcnc, fanuc, haas, mach3 | `true`, `false` (left out) | left out: drilling and threading cycles are canned cycles, lathe roughing is plain moves; `true`: every cycle the controller has (Fanuc/Haas `G71`); `false`: every cycle as plain moves |
| `program_number` | fanuc, haas, wire_edm | 1 to 9999 (99999 Haas) (1000) | the `O` number |
| `smoothing` | haas | `off`, `rough`, `medium`, `finish` (`off`) | `G187 P1`..`P3 E<tolerance>` |
| `dwell_ms` | mach3, plasma, waterjet | `true`, `false` (`false`) | `G4 P` in milliseconds (Mach's "G4 dwell in ms" setting) |
| `torch_z` | mach3, plasma | (`true`) | write the torch heights as Z moves |
| `pierce_height_mm`, `cut_height_mm`, `safe_height_mm` | mach3, plasma | mm (3.8, 1.5, 10) | the torch heights |
| `z_feed_mm_min` | mach3, plasma | mm/min (1000) | the feed down to cut height |
| `pierce_delay_s` | mach3, plasma | s (0.5) | the pierce delay when the operation gives none |
| `thc`, `thc_on`, `thc_off` | mach3, plasma | (`false` on mach3, `true` on plasma), (`M101`, `M102`) | torch height control around each cut; the codes are placeholders: set your controller's |
| `pierce_s` | waterjet | s (1) | the pierce dwell when the operation gives none |
| `laser_scale` | marlin | `255`, `1000` (255) | the S value of full power |
| `laser_mode` | marlin | `constant`, `dynamic` (`constant`) | `M3`, or `M4` (power with speed, Marlin 2.1+) |
| `inline_power` | marlin | (`false`) | `M3 I` inline mode: `S` on every cutting move, `S0` on the next rapid |
| `z_words` | marlin, waterjet | (`false`) | post the toolpath's Z |
| `wire_comp` | wire_edm | `applied`, `controller` (`applied`) | applied: the path is the wire centre, `G40`; controller: `G41`/`G42 D1` per cut, D1 holding only a wear or skim adjustment |
| `uv_words` | wire_edm | (`false`) | taper as explicit `U V` words (lite: the lean turns over the move after a sharp corner) instead of `G51`/`G52 A` |
| `wire_thread`, `wire_cut` | wire_edm | (`M50`, `M60`) | the thread-the-wire and cut-the-wire codes; the wire is cut only when the table travels to another start hole |

## Multi-axis and lathes

- **3+2** (a tilted setup): LinuxCNC and Mach3 turn the table (`G0 A.. C..`) after each tool change: set
  the setup's work offset on the turned part. Fanuc enters a tilted working plane (`G68.2 X0 Y0 Z0 I J K`,
  `G53.1`, out with `G69`) and Haas a dynamic work offset (`G254`, out with `G255`): there the work offset
  is the setup's origin on the part with the table at zero.
- **Simultaneous** (rotary axes change while cutting): A/B/C on every move, no arc fitting, tool length as
  tool centre point control (`G43.4`; Haas `G234`). Stock LinuxCNC has no `G43.4`: it needs a TCP
  kinematics configuration that provides it. Mach3 has no TCP: a wrap there is refused.
- **Lathe**: X is a diameter (radius with `machine.diameter_mode: false`), arcs are `G18` with I a radius.
  Constant surface speed posts with its rpm clamp; feed per revolution where the operation asks.
  Threading is the controller's `G76`; a tapered thread posts as plain moves on LinuxCNC. A lathe never
  gets `G90` from Fanuc or Haas (it is a turning cycle there).

## Refusals

A program the machine cannot run is refused in one sentence, and nothing is written: a beam on a mill,
a spindle or coolant on a cutting table (air assist is allowed on a laser), a rotary axis the machine
does not have, a lathe move off the XZ plane, a drilling cycle on a wire EDM, `wire_comp: controller`
without the cut's side, `uv_words` taper without the cut's thickness, an `O` number too big.

## Reading the result

The CLI's JSON names each setup's posted file. Open it and check the header, the work offset, the tool
list and the first moves before you report. Canned cycles posted natively follow the controller's own
retract and pass rules (a Fanuc `G73` retract is a machine parameter), so the program can differ from the
viewer's simulated path inside a cycle; the viewer shows the plain moves the cycle stands for.
